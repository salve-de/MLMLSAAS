# MLMLSAAS — Seller Network

デジタル商品マーケットと、実売上に基づく多段紹介ネットワークの実装です。
**画面だけではなく、認証・SQLite永続化・紹介記録・報酬台帳・商品審査のAPIが動作します。ただし決済画面・実送金は未接続のMVPです。**

## すぐ試す

Node.js 22.13以上。ローカル検証環境は22.16.0です。アプリのnpm依存パッケージ・ビルド工程はありません。

```sh
npm run demo
# http://localhost:3000 を開き「デモで試す」
```

デモは `data/demo.db` に永続化。サンプル商品6件、紹介者・下位紹介者、別のテスト購入者を用意します。「直接売上をテスト」「下位売上をテスト」「直近売上を返金」で台帳が変化します。デモでは保留期間を0にし、全額を換金不可のテスト残高として表示します。ヘッダーの「運営画面を試す」で商品審査も確認できます。

デモDBと本番DBは別ファイルです。`NODE_ENV=production` または実課金・出金有効時にデモを起動しようとすると停止します。デモの売上・残高・商品は本番に移行しないでください。`.env` は不要で起動できます。

## 実装範囲

| 領域 | 動作 |
|---|---|
| マーケット | カテゴリ・検索・価格/報酬率での並び替え、商品詳細、PR表記付き紹介文 |
| アカウント | 無料登録、scryptパスワード、HttpOnlyセッション、ログアウト |
| 紹介 | 専用URL、30日first-touchの商品別アトリビューション、クリック重複排除、登録時の紹介元固定 |
| ネットワーク | 固定階層上限なし、子孫のみ閲覧、50件ずつページング、メール等は下位紹介者に非公開 |
| 商品提供者 | 商品申請、公開審査、公開/非公開切替、価格・直接報酬率・ネットワーク原資 |
| 報酬 | 整数円計算、固定総額内の逓減配分、継続売上、append-only台帳、保留/確定残高 |
| 返金 | 全額返金の正確な逆仕訳、二重取消防止、支払後はマイナス残高の繰越 |
| 出金 | 残高予約、申請IDによる冪等性、運営CSV、外部の実送金番号を照合して記録。デフォルト無効 |
| 課金連携の境界 | 署名検証付きの正規化イベント受信API。特定の決済会社のアダプターは未実装 |
| 運営 | 商品審査、出金確認、監査ログ、healthcheck、Docker構成、CI |

売上・成約率・継続率・EPCを架空の実績として埋めていません。デモ商品自体のSaaS機能、外部サービスのアカウント作成・利用権発行は含まれません。

## 本番用アカウントの準備

```sh
cp .env.example .env
# APP_SECRET / BASE_URL等を設定
# ADMIN_EMAIL / ADMIN_PASSWORD（12文字以上）を一時的に設定
npm run admin
# ADMIN_PASSWORDは設定から削除
npm start
```

最初の一般登録者を管理者にする処理や、ソースコードに埋め込まれた管理者パスワードはありません。`npm run admin` は既存アカウントを上書き・権限昇格しません。

## デプロイ

Node.js常駐プロセス1個と永続ディスクで起動する構成です。ホスティング以外の企業提携、外部DB、AI APIはデモ起動に不要です。

```sh
# .envのBASE_URLを実際のHTTPSオリジンに、APP_SECRETを十分長い乱数に設定
# 既存のTLSリバースプロキシから127.0.0.1:3000に転送
# 適切なバックアップを別途設定

docker compose up -d --build
# コンテナ内DBに管理者を作る場合（ADMIN_*の一時設定が必要）
docker compose exec app node scripts/admin.mjs
```

Dockerは配布用設定を用意した段階で、この作業環境ではビルド未検証です。`node:sqlite` はNode 22ではexperimental警告が出ます。Node 22/24のCIを追加しています。

**Vercel Functions/Cloudflare Workersに、このSQLiteファイル方式をそのまま配置しないでください。** 永続DBアダプターへの置き換えが必要です。水平スケール、複数インスタンス、外部販売者の大量受け入れも、この初期構成の検証対象外です。

## テスト

```sh
npm run check
npm test
```

整数配分の保存則・2,000パターンの配分・2,000階層の紹介関係・冪等性・返金・出金予約・権限・CSRF・署名・CSV式注入対策等を検証します。HTTP統合テストは一時インメモリDBとローカルHTTPサーバーを実際に起動します。

UIのブラウザテスト手順は `docs/QA.md`。ブラウザからローカルURLへの接続が制限された作業環境のため、今回の見た目確認はオフライン描画です。オンラインのブラウザE2Eが通ったとは主張していません。

## 本番課金前に必要な作業

`docs/LAUNCH.md` に未接続箇所と公開前のゲートを記載しています。**このPRをマージするだけで、課金・自動送金・適法性の確認が完了するわけではありません。** 実際の商品、決済事業者による事業モデルの承認、本人確認・税務・表示・運用体制は別途必要です。

詳しい計算仕様・イベント契約・制約は `docs/ARCHITECTURE.md` を参照してください。
